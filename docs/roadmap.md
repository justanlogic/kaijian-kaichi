# Roadmap

> 版本计划会随反馈调整。想要某个功能，欢迎开 Issue 说明使用场景；场景比“+1”更有用。

## v1.7.1 · 当前

- `?demo=1` 演示模式：示例数据、避免覆盖真实记录、隐藏云登录
- 修复：食物搜索后未点选直接保存，会落到默认食物
- README 重写 + 英文版 + `docs/` 文档 + Issue 模板
- 统一“数据默认在本机，云同步可选”的表述

## v1.8.0 · 从记录到复盘

**目标：让记录产生反馈，而不是只进不出。**

- 周报：本周训练容量、日均热量、蛋白质达标天数、体重变化
- CSV 导出：训练 / 饮食 / 身体数据三张表
- 可分享的周报卡片（不含隐私明细，可自选是否显示体重）
- 可访问性第一批：浅色主题对比度 ≥ 4.5:1、图标按钮触控目标 ≥ 44px

**验收**：周报数据与明细一致；导出可被 Excel / Numbers 打开；对比度用工具检查通过。

## v1.9.0 · 换设备不丢数据

**目标：降低迁移成本，解决多账号同设备的缓存问题。**

- 导入 Strong / Hevy 的 CSV（训练）
- 同设备多账号时，本机缓存按 `owner_id` 分桶，切换账号不串数据
- 评估 localStorage → IndexedDB 迁移（记录量超过 5MB 时）

**验收**：导入 100 条训练不重复、不丢组数；两个账号在同一浏览器互不可见；旧数据可无损迁移。

## v2.0.0 · English & mobile

**目标：让非中文用户也能用，而不只是看懂 README。**

- 英文界面（i18n，至少覆盖四个页面与弹层）
- 香港常见食物包（茶餐厅、点心、烧味）
- PWA Share Target：从其他 App 分享文本/图片到开健开吃
- 可选：每周回顾提醒（本地通知，不依赖服务器）

**验收**：英文界面无硬编码中文；香港食物包有来源；Share Target 在 Android Chrome 可用。

## 明确不做

- 社交动态、排行榜、好友 PK：与“本地优先、低负担”的定位冲突。
- 医疗 / 诊疗建议：只做记录与通用营养参考。
- 一万条食物库：优先覆盖“中国日常 + 地区特色”，不拼数量。
- 广告、订阅、卖数据：不做。
- 强制登录：不登录必须能完整使用。

## 如何影响优先级

开 Issue 时写清：

1. 你在什么场景下需要它？
2. 现在你怎么解决？
3. 如果没有它，会损失什么？

三个问题比“求加 XX”更容易被排进版本。
