## 命名规范

1. **主体名 + 必要状态**：状态写在中文全角括号里，只保留影响营养或区分度的那一个，如「鸡胸肉（熟）」「燕麦片（干）」「金枪鱼（水浸）」「鸡腿肉（去皮）」。
2. **不写品牌、门店、口味修饰**：名称用通用叫法，品牌写进别名。如「巨无霸」的别名是「麦当劳巨无霸」，搜「麦当劳」能一次筛出该店全部条目，名称本身保持通用。
3. **同物不同状态拆两条**：生熟、干鲜、全脂脱脂差异大的分开建条目；差异可忽略的不拆（避免「米饭」和「白米饭」并存）。
4. **同物异名只加别名，不新建条目**：别名写在 `alias` 字段，英文逗号分隔，如番茄的 `alias: '西红柿'`。
5. **统一用中文常用名**，不加空格与书名号；已通行的英文缩写（如 GI、DHA）保留原写法。

## 营养口径

- 统一按**每 100g 可食部**（饮品按 100ml）记录热量、蛋白质、碳水、脂肪；`amount` 是默认一份的克数。
- 热量为常见参考值；蛋白质 / 碳水按 4 kcal/g、脂肪按 9 kcal/g 折算。
- 因膳食纤维与酒精不计入碳水，蔬菜、菌藻与酒类的折算值会低于标称热量，属正常。
- 默认按**熟制、带皮、带酱汁**记录；带皮烧腊的脂肪集中在皮下，去皮后大约减半。

## 判断食物是否已存在

新增前按以下顺序检查：

1. **跑自检脚本**

   ```bash
   node scripts/check-foods.mjs
   ```

   会输出总数、分类分布，并检查：
   - `id` / 名称 / 别名三组命名空间是否重复；
   - 分类是否存在；
   - 数值是否合法；
   - 热量与三大营养素是否严重不自洽（偏差 >22% 时提醒）。

2. **规范化比较**：脚本会把名称做 NFKC 归一、转小写、去掉空格与 `（）()·、,` 等符号后比较，所以「番茄」「番茄 」不会被当成两条。

3. **先搜别名再决定**：在应用内搜索候选名或俗称（如「西红柿」「车厘子」「地瓜」），能搜到就说明已有条目，只需补别名。

4. **判定规则**：
   - 同物异名 → 加到已有条目的 `alias`，不新增；
   - 同名但状态不同且营养差异明显 → 用括号区分后新增（如「牛奶（全脂）」与「脱脂牛奶」）；
   - 只是份量不同 → 不新增，用份量输入框调整。

## 新增一条食物

1. 在 `js/data.js` 对应分类下追加：

   ```js
   { id: 'f-example', name: '示例食物（熟）', cat: '肉蛋', kcal: 200, p: 20, c: 5, f: 10, amount: 100, alias: '别名1,别名2' },
   ```

2. `id` 用 `f-` 前缀 + 英文短名，保持唯一；`alias` 可省略。
3. 跑 `node scripts/check-foods.mjs`，确认无重复、无分类错误、无严重数值偏差。
4. 在 PR 描述里写清：名称、分类、每 100g 数值、来源（成分表页码 / 品牌链接 / 参照数据）。
5. 数量变化时更新 `README.md` 与本文档的分类表。

## 常见问题

- **为什么菠菜热量和 4/4/9 折算差很多？** 膳食纤维不计入碳水，蔬菜尤其明显；这是正常现象，不是录入错误。
- **为什么酒的热量也偏低？** 酒精 7 kcal/g 不计入三大营养素，折算值会低于标称热量。
- **为什么同一种食物有两个条目？** 生熟、干鲜、带皮去皮的差异可能超过 20%，拆开更准确；如果差异小，应该合并并加别名。
